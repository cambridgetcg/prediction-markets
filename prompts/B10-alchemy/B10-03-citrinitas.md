## The Golden Design

### Design Principle 1: The Execution-First Architecture

Using the Coniunctio Statement from ALBEDO, redesign the system so that
building and trading are the same act.

**Question**: If you could only have 5 active components (not 69 prompts),
what would they be? Design the minimal system that actually TRADES.

```markdown
Component 1: _____________ (purpose: _____________)
Component 2: _____________ (purpose: _____________)
Component 3: _____________ (purpose: _____________)
Component 4: _____________ (purpose: _____________)
Component 5: _____________ (purpose: _____________)
```

Everything else is either:
- Support infrastructure for these 5 (justified)
- Beautiful but unnecessary (cut or archive)

### Design Principle 2: The Feedback Ouroboros

The system's deepest failure is lack of feedback loops.
Trades don't flow back into calibration automatically.
Calibration doesn't adjust strategy parameters automatically.
Strategy performance doesn't prune the strategy set automatically.

Design the feedback architecture:

```
TRADE → OUTCOME → CALIBRATION → STRATEGY ADJUSTMENT → BETTER TRADE
  ↑                                                           │
  └───────── the system improves itself through trading ──────┘
```

For each arrow, specify:
- What data flows?
- What triggers the flow? (Automatic or manual?)
- What changes as a result?
- How fast does the loop close? (Hours? Days? Weeks?)

### Design Principle 3: The YES Integration

The YES blindspot is not a parameter to tune. It's a perspective to integrate.

Design a structural mechanism that forces YES consideration:

**Options to evaluate:**
1. **Mandatory YES pre-mortem** on every trade (already in E01 — is it enough?)
2. **YES-only sprints** — periodic weeks where only YES positions are taken
3. **Devil's advocate prompt** — a prompt that argues FOR the event happening
4. **Dual-estimation** — always estimate both YES and NO independently, check they sum to ~100%
5. **YES specialist persona** — a distinct analytical voice that only looks for YES evidence
6. **Outcome base rate correction** — what % of Polymarket markets actually resolve YES? Use this as prior

Which mechanism(s) belong in the golden architecture? Why?

### Design Principle 4: The Capital Ladder

Design a concrete, no-ambiguity graduation path from $28.98 to $1,000+:

```
Stage 1: $30   — Current. System test. ≤3 positions.
Stage 2: $___  — Triggered by: [specific criteria]
Stage 3: $___  — Triggered by: [specific criteria]
Stage 4: $___  — Triggered by: [specific criteria]
Stage 5: $1000 — Triggered by: [specific criteria]
```

The criteria must be:
- Measurable (not "when I feel confident")
- Time-bound (not "eventually")
- Falsifiable (if criteria not met by date X, reassess entire approach)

### Design Principle 5: The Signal Hierarchy

The system currently treats all signals equally. Design a clear hierarchy:

```
Level 1: Information (read about it)
         → Action: Log. No trade.

Level 2: Thesis (have a view + evidence)
         → Action: Paper trade.

Level 3: Edge (thesis + market mispricing + strategy fit)
         → Action: Small live trade (Stage 1-2 sizing).

Level 4: Conviction (edge + whale confirmation OR news pipeline signal)
         → Action: Standard live trade (quarter-Kelly).

Level 5: Convergence (edge + whale + news pipeline + fresh wallet)
         → Action: Maximum sizing (half-Kelly, within caps).
```

For each level: what SPECIFIC evidence promotes a signal to the next level?
No vague criteria. Concrete, checkable conditions.

### Design Principle 6: The Pruning Protocol

The system has accumulated components without a pruning mechanism.
Design a quarterly review that asks of every component:

```
For each prompt / strategy / script / data file:
1. Has this been USED in the last 90 days?
2. Has this contributed to a TRADE in the last 90 days?
3. If neither: ARCHIVE it (move to /archive, out of active prompt set)
4. If archived for 2 consecutive quarters: DELETE it
```

What does the system look like after the first pruning?
Run the pruning protocol mentally against the current 69 prompts.
How many survive?

### Design Principle 7: The Sacred Schedule

The system lacks rhythm. Design the operating cadence:

```
DAILY (15 min):
  - [ ] _______________
  - [ ] _______________

WEEKLY (1 hour, e.g. Sunday evening):
  - [ ] _______________
  - [ ] _______________
  - [ ] _______________

MONTHLY (2 hours, first of month):
  - [ ] _______________
  - [ ] _______________

QUARTERLY (half day):
  - [ ] _______________
  - [ ] _______________
```

Every item must serve one of the 5 core components from Design Principle 1.
If it doesn't, it doesn't belong in the schedule.

## The Beauty Test

Before finalising the golden architecture, apply the Beauty gates:

- **B1 Foundation**: Is every design decision grounded in evidence from NIGREDO/ALBEDO?
- **B2 Emerged**: Did the design emerge from understanding, or was it forced?
- **B3 Fits**: Does this design fit Yu's actual life (time, capital, attention)?
- **B4 Elegant**: Is anything extra? Is anything missing?
- **B5 Coherent**: Do all 7 design principles form a unified whole?
- **B6 Clear**: Could Yu execute this tomorrow without further explanation?
- **B7 Appropriate**: Is this right-sized for the system's actual stage ($28.98, not $10K)?
